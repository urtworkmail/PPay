Product Updates

Track our progress as we build Pakistan's payment infrastructure platform. All notable architectural changes and feature releases are logged here.

v3, Core architecture rebuild

In progress

Multi-phase rebuild bringing PPay onto a single PaymentIntent orchestration core, matching modern payment architectures and workflows.

Phase 3, No-delete data policy & audit log

  • ✓
    No hard deletes
    Audited every mutating endpoint. Two real hard deletes were found and converted to soft state changes that preserve history. Every other "delete" route already soft-deactivates.
  • ✓
    Audit log
    Every account-affecting action is now recorded in an append-only log, with the acting team member's identity attached to each entry.

Phase 2, PaymentIntent/Charge orchestrator

  • +
    Payment Intent Engine
    Implemented get_or_create_payment_intent and record_charge_attempt, which handles state machine transitions including ambiguous failures.
  • +
    Dual-writes enabled
    Checkout's pay endpoint and subscription off-session billing now write a PaymentIntent/Charge pair alongside their existing Transaction write.

Phase 1, Data model unification & test/live schema separation

  • +
    Sandbox/production schema separation
    Implemented two real Postgres schemas (sandbox, production) instead of a boolean flag, resolved automatically via API key prefixes.
  • +
    New core entities
    Added Customer, PaymentIntent, Charge, Coupon, Discount, Dispute, LedgerEntry, ReconciliationRecord, Event.
  • +
    Mode-prefixed public references
    Introduced prefixes like cs_sandbox_... to automatically route anonymous buyers to the correct schema.
