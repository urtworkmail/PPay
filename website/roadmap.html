Phase 1 · Shipped

Live in sandbox today

Payment acceptance
Hosted Checkout for card, wallet, and bank transfer. Payment Links with usage tracking. Invoicing with auto-numbering and a hosted pay link. Subscriptions with saved methods and a 3-attempt dunning schedule.
Checkout Links Invoicing Subscriptions
Risk & compliance
Sentinel scores every checkout attempt on six deterministic signals and blocks at 75 before any rail is called. Disputes carry a 7-day response clock. Tax estimates cover five provincial authorities.
Sentinel Disputes Tax
Money movement & insight
Nightly settlement batching with itemised gross, fee, and net. Payout scheduling on a daily, weekly, or monthly cadence. Micro-deposit verification of the payout account. Analytics with per-method success rates.
Payouts Analytics Connections
Developer platform
REST API with required idempotency keys on session creation. An immutable event log written whether or not a webhook endpoint exists. HMAC-signed webhook delivery with exponential retry backoff across five attempts.
API Webhooks Events
Accounts & security
Four roles with real permission boundaries. TOTP two-factor authentication. Per-device session binding with remote revocation. An audit log entry on every account-affecting action, and a no-delete data policy.
Team & Security Notifications
Operations
Schema-separated sandbox and production data, so cross-mode leakage is structurally impossible. Rate limiting, startup secret checks, nightly database backups, and a written restore runbook. A live per-capability status page.

Phase 2 · In progress

Being worked on right now

Licensed partner arrangement
The single thing standing between sandbox and real money. PPay is a software layer and will not custody funds. We are structuring the arrangement with a licensed bank or PSP that will hold funds, run settlement, and carry the regulatory permissions. That structure determines the final legal position of the platform, and this page gets updated when it is settled.
Blocks: real money movement, live API keys, merchant go-live.
Go-live review and merchant KYC
The review flow that gates a merchant moving from sandbox to live. Merchants submit business and bank details for manual review. There is deliberately no code path that auto-approves real-money processing, and there will not be one.
Status: submission and review states are built; approval stays manual by design.
Mobile dashboard
The merchant dashboard is desktop-only today. The hosted checkout page your customers see is already mobile-optimised; it is the operator dashboard that is not. A mobile experience is in progress.
Today: signing in from a phone shows a desktop-only notice with contact details.
Local rail integrations
Wallet and bank-transfer flows work end to end against the sandbox engine. Connecting them to the real JazzCash, Easypaisa, 1LINK, and Raast rails depends on the partner arrangement above, since those integrations are made through a licensed entity rather than directly.
Depends on: the licensed partner arrangement.
Phase 3 · Not started

On the list, not yet begun

Real money movement
Every transaction today is a sandbox construct. No real funds move anywhere until the partner arrangement is finalised, and we would rather say that plainly than imply otherwise.
Sentinel custom rules
A no-code rule builder with per-account thresholds ("block if amount is over X and the customer is new"). Today's 75-point threshold is fixed and identical for every account.
Device fingerprinting
Sentinel's velocity signals currently key on IP address and email only. True device fingerprinting would catch rings that rotate both.
Automatic dispute evidence
Pulling the risk score, signals, and transaction history into a dispute response automatically, instead of you writing the evidence text by hand.
Marketplaces and split payments
Routing a single payment to multiple recipients, with per-seller balances and payouts. Today a settlement batch belongs to exactly one merchant.
In-person payments
Card-present terminals and QR-based collection. Everything today is online-only, and card-present is a hardware and certification problem rather than a software one.
Ecommerce plugins
WooCommerce, Shopify, and Magento integrations. The REST API is there to build against; the packaged plugins are not written.
Client SDKs
Official libraries for Node, PHP, and Python. Today the API is plain REST, which works everywhere but means you write the HTTP calls yourself.

Everything above runs in sandbox

PPay is a technology layer, not a bank. We do not hold a PSO/PSP or EMI licence and we do not custody merchant or customer funds. A licensed partner will. Until that arrangement is finalised there are no live transactions and no real money movement, only test credentials. A payments company that overstates what it does is a payments company you should not trust with money.
